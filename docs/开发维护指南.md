# 开发维护指南

本指南面向维护游戏代码的开发者。该项目是无构建步骤的浏览器原生 ES 模块应用，所有示例命令均从项目根目录运行。

## 环境与启动

需要 Node.js 与 Python 3。项目不依赖 npm 包，`package.json` 仅声明 ES 模块模式。

在项目根目录运行静态服务器：

```powershell
python -m http.server 50967 --bind 127.0.0.1
```

访问 <http://127.0.0.1:50967/> 预览。停止服务器可在运行服务器的终端按 `Ctrl+C`。如果本机没有 Python 3，可使用任意仅监听本机地址的静态 HTTP 服务器；直接以 `file://` 打开并非项目验证方式。

## 测试

运行完整 Node.js 内置测试套件：

```powershell
node --test
```

仅运行某一测试文件时，例如：

```powershell
node --test tests/rhythm.test.mjs
```

测试按档案、音频、谱面、输入、导航、设置、展示、经营、判定、舞台和存档模块组织在 `tests/` 下。本项目没有定义 npm test/build 脚本，不要使用 `npm run build` 或假设存在打包产物。

## 重要行为约定

- 三场谱面和难度都以 `src/content.js` 为准；每场使用当前播放时钟判定，不要从页面帧率推导命中时间。
- 键位映射由 `src/lane-input.js` 单一维护，轨道顺序为 `A S D F H J K L`。
- `src/rhythm.js` 中的准确率只基于 Perfect/Good/Miss 基础分；阶段倍率、难度分数倍率和连击加分只影响分数。
- 赛季进度、设置和赛季档案是分开的本地记录；修改其存储契约前先检查 `tests/storage.test.mjs`、`tests/preferences.test.mjs` 与旧版兼容测试。
- 背景视频和字体在 `index.html` 中引用外部资源。离线访问时这些视觉资源可能无法载入，但本地游戏代码仍由静态服务器提供。
- 修改演出页绑定、判定、输入或暂停恢复流程后，先运行 `node --test tests/performance-controller.test.mjs`，再运行完整 `node --test`；视觉改动还应检查桌面与手机尺寸及控制台。
- 保持 `styles.css` 中的导入顺序。新增规则应进入职责最接近的样式文件；只有需要有意覆盖前面规则时才使用 `08` 至 `12` 的覆盖层，不要通过在入口文件或最终文件反复追加同名选择器解决优先级问题。
- `tests/presentation.test.mjs` 会按照 `styles.css` 的导入顺序读取全部样式模块。拆分或重命名样式文件后，应同步入口导入和展示测试，不能通过删除视觉断言规避失败。

## 修改后的检查

完成改动前，从项目根目录运行：

```powershell
node --test
```

如改动包含浏览器交互，再按「环境与启动」中的命令启动本地服务器，检查实际界面、键盘和触屏布局。文档中出现的命令、相对链接和模块路径应与当前项目保持一致。
