# 拉取文件规范

本规范用于安全地克隆、拉取和同步项目文件，避免本地改动被覆盖或把无关文件带入仓库。命令均从项目目录执行。

## 首次获取项目

使用仓库页面提供的 HTTPS 地址克隆，然后进入项目目录：

```powershell
git clone https://github.com/<仓库所有者>/gamelvdong.git
Set-Location gamelvdong
```

私有仓库需要已登录且有访问权限的 GitHub 账号。克隆完成后运行：

```powershell
git remote -v
git status
node --test
```

## 日常同步流程

拉取前先确认当前分支和工作区状态：

```powershell
git branch --show-current
git status
```

如果工作区干净，同步远程引用并仅允许快进更新：

```powershell
git fetch --prune origin
git pull --ff-only origin main
node --test
```

`--ff-only` 会在本地与远程历史分叉时停止，避免自动生成意外的合并提交。

## 有本地改动时

不要在未检查的情况下直接拉取。根据改动状态选择一种方式：

1. 已完成的改动：按[提交规范](提交规范.md)检查、提交后再同步。
2. 尚未完成但需要保留的改动：执行 `git stash push -u -m "同步前临时保存"`，同步完成后执行 `git stash pop`，并立即检查冲突。
3. 不需要的单个文件改动：确认文件路径和内容后，只处理该明确文件；不要使用递归删除或会覆盖整个工作区的命令。

## 分支发生分叉时

当 `git pull --ff-only` 拒绝更新时，先获取远程状态并查看差异：

```powershell
git fetch origin
git log --oneline --graph --decorate --all -20
```

不要使用 `git reset --hard`、强制推送或未经确认的历史改写。保留本地提交，并根据团队约定选择合并或变基；解决冲突后运行 `node --test`，再提交和推送。

## 冲突处理

- 使用 `git status` 查看冲突文件，只编辑列出的文件。
- 对每个冲突保留正确内容，移除冲突标记 `<<<<<<<`、`=======` 和 `>>>>>>>`。
- 运行相关单项测试，再运行完整 `node --test`。
- 使用 `git diff --check` 检查残留冲突标记和空白错误。
- 无法确定应保留哪一侧时停止操作，联系该功能的维护者确认。

## 禁止事项

- 不要提交账号密码、访问令牌、私钥或 `.env` 文件。
- 不要绕过测试直接覆盖 `main`。
- 不要在共享分支使用强制推送。
- 不要用递归删除命令清理仓库；需要删除多个文件时，由维护者逐项确认并手动处理。
