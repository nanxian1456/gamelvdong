# 演出控制模块拆分设计

日期：2026-10-09  
状态：已实施

## 背景

页面模板已经从 `src/main.js` 提取到 `src/views.js`，但演出流程仍集中在 `main.js`。当前演出代码同时管理音频引擎、节奏 runtime、键盘与触屏输入、Canvas 尺寸、HUD 缓存、动画帧、暂停恢复和演出结算。这些职责共享大量可变变量，使页面路由和赛季编排必须了解演出的内部生命周期。

本次拆分的目标是建立一个演出控制模块，让 `main.js` 只负责赛季状态、路由、存档、经营和结算编排。拆分不得改变现有玩法、判定、自动开始、后台暂停、恢复演出或界面结构。

## 设计目标

- 将一次演出的完整浏览器生命周期集中到一个深模块中。
- 缩小 `main.js` 对演出内部状态的了解范围。
- 保持现有 `rhythm.js`、`audio.js`、`controls.js`、`stage.js` 和 `views.js` 的职责。
- 允许使用伪音频引擎验证控制模块的生命周期，而不依赖真实 Web Audio。
- 保持所有现有测试、存档格式和玩家可见行为不变。

## 非目标

- 不修改谱面、判定窗口、计分或经营规则。
- 不重新设计演出界面或 CSS。
- 不改变本地存档结构。
- 不引入框架、构建工具或第三方依赖。
- 不在本阶段拆分经营与结算控制逻辑。

## 模块与接缝

新增 `src/performance-controller.js`。该模块是演出生命周期的唯一外部接缝，隐藏 runtime、音频、输入、HUD 和动画帧的实现细节。

模块通过 `createPerformanceController(options)` 创建。创建参数包含：

- `root`：应用内容根节点。
- `windowTarget` 和 `documentTarget`：浏览器事件目标。
- `createEngine`：音频引擎工厂；生产环境使用 `createAudioEngine`，测试使用伪音频引擎。
- `onComplete(summary)`：演出完成后的回调。
- `onPreferenceChange(changes)`：演出页静音操作产生的偏好变更回调。

控制模块返回以下接口：

```js
{
  enter(options),
  leave(),
  setPreferences(preferences),
  dispose(),
}
```

### `enter(options)`

进入演出页面。参数包括当前 `campaign`、`show`、难度、偏好、存档可用状态、是否为恢复中的演出以及是否自动开始。

行为：

- 使用 `renderPerformanceView` 生成演出页面。
- 绑定静音、开始、暂停、恢复和轨道输入。
- 初始化 Canvas、HUD 引用和尺寸。
- 如果已有暂停会话，则从原播放位置恢复。
- 如果没有会话且 `autoStart` 为真，则立即创建并启动会话。
- 如果没有会话且 `autoStart` 为假，则等待玩家点击开始按钮。

重复调用 `enter` 不得创建重复音频引擎或重复输入监听器。

### `leave()`

离开演出页面但保留当前演出会话。

行为：

- 暂停音频时钟。
- 清空物理按键和触摸按住状态。
- 取消动画帧。
- 解除当前页面的输入与控件绑定。
- 保留 rhythm runtime，使返回演出页时可以继续。

没有活动会话时调用是安全的空操作。

### `setPreferences(preferences)`

保存控制模块使用的最新偏好，并立即同步静音和音量到活动音频引擎。降低动态效果和延迟校准在后续绘制、输入和 HUD 更新中读取最新值。

### `dispose()`

彻底结束演出会话。

行为：

- 执行 `leave()` 的清理。
- 销毁音频引擎。
- 丢弃 rhythm runtime、HUD 缓存、Canvas 引用和判定涟漪。
- 可以重复调用且不会重复完成演出或重复销毁资源。
- 控制器实例在销毁当前会话后仍可用于下一赛季；后续 `enter()` 会重新初始化需要的监听器和状态。

## 职责归属

`performance-controller.js` 拥有：

- rhythm runtime 和完成状态。
- 音频引擎的创建、启动、暂停、恢复和销毁。
- `requestAnimationFrame` 循环及帧间时间。
- 键盘、触屏和指针输入绑定。
- Canvas 尺寸、绘制上下文、舞台几何和窗口 resize 处理。
- HUD 缓存、得分/连击/准确率/进度更新。
- 判定文字、动画反馈和下一拍提示。
- 页面隐藏时的自动暂停。

`main.js` 保留：

- 赛季 `campaign` 状态。
- 页面路由和导航历史。
- 设置与赛季状态持久化。
- `settleShow` 调用以及演出完成后的页面切换。
- 经营行动和最终结算流程。

`views.js` 保留：

- 演出页面纯 HTML 模板。
- 不读取浏览器全局状态，不注册事件。

## 数据流

### 新赛季自动开始

1. `main.js` 创建并保存新赛季状态。
2. `main.js` 调用 `controller.enter({ autoStart: true, ... })`。
3. 控制模块渲染页面、创建 runtime 和音频引擎，并启动倒数。
4. 控制模块处理输入与动画帧。
5. rhythm runtime 完成后，控制模块销毁会话并调用 `onComplete(summary)`。
6. `main.js` 调用 `settleShow`、保存赛季并渲染经营页或结算页。

### 离开和返回演出

1. 路由离开演出页前，`main.js` 等待 `controller.leave()`。
2. 控制模块暂停音频并解除页面绑定，但保留 runtime。
3. 返回演出页时，`main.js` 再次调用 `controller.enter(...)`。
4. 控制模块重新渲染和绑定页面，然后恢复原播放位置。

### 页面刷新后的恢复

刷新会丢失内存中的 runtime，但存档仍表明赛季处于演出阶段。`main.js` 将 `restoredActiveShow: true` 传给控制模块。页面显示现有“本场演出待继续”提示，玩家点击后从三秒倒数重新开始该场。

## 错误处理与生命周期约束

- 音频创建失败时继续使用 `audio.js` 已有的单调时钟回退，不中断演出。
- 所有公开生命周期方法均可重复调用；重复调用不得注册重复监听器或创建重复帧循环。
- `onComplete` 每场最多调用一次。
- 完成回调抛错时，控制模块仍必须释放音频和输入资源；错误继续向调用方传播或由浏览器报告，不重复结算。
- 页面隐藏只暂停活动且未暂停的会话。
- `leave()` 与 `dispose()` 必须先重置按住输入，避免返回页面后残留长按状态。
- 每个活动会话最多注册一个 resize 处理器；`dispose()` 将其移除，后续新会话进入时重新注册。

## 测试策略

新增 `tests/performance-controller.test.mjs`，通过控制模块接口验证可观察行为：

- `enter({ autoStart: true })` 只创建并启动一个音频引擎。
- 重复进入不会重复绑定输入或启动第二个动画循环。
- `leave()` 暂停引擎、重置输入并保留 rhythm 进度。
- 再次 `enter()` 恢复同一会话。
- `setPreferences()` 立即同步静音和音量。
- 页面隐藏会暂停活动会话。
- 完成演出只调用一次 `onComplete`。
- `dispose()` 销毁引擎并移除所有监听器，且可以重复调用。
- 音频不可用时仍可通过回退时钟完成演出。

测试使用伪音频引擎和最小 DOM 测试适配器。旧的源码正则测试在控制模块接口测试覆盖相同行为后删除或改为接口测试，避免跨越模块接缝检查内部实现。

最终验证包括：

- `node --test`
- `node --test --experimental-test-coverage`
- 所有 `src/*.js` 的 `node --check`
- 浏览器中新赛季自动开始、暂停/恢复、离开/返回演出、手机八轨布局和控制台检查

## 实施顺序

1. 先为控制模块接口编写失败的生命周期测试。
2. 创建控制模块并迁移 runtime、音频和输入生命周期。
3. 迁移 Canvas、HUD、判定反馈和动画帧。
4. 将 `main.js` 改为通过控制模块接口进入、离开和完成演出。
5. 删除 `main.js` 中已迁移的状态与函数。
6. 更新维护文档及依赖源码位置的旧测试。
7. 运行完整自动化与浏览器验证。

## 完成标准

- `main.js` 不再保存 runtime、HUD、Canvas、动画帧或输入绑定状态。
- `main.js` 不直接创建或操作音频引擎。
- 演出控制模块的外部接口仅包含 `enter`、`leave`、`setPreferences` 和 `dispose`。
- 所有现有玩家行为和存档兼容性保持不变。
- 新旧自动化测试全部通过，浏览器演出流程无控制台错误。
