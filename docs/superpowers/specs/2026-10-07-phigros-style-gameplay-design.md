# 自由判定线节奏玩法设计（历史方案）

状态：已被当前八轨钢琴块玩法取代；仅保留作设计沿革，不代表当前实现。  
日期：2026-10-07

> 本文记录早期自由判定线与多手势方案，包含斜判定线、A/D 移动和空格输入等现已不适用的设想。当前版本使用八条固定轨道、`A S D F H J K L` 对应按键，以及点击和长按音符。请以[玩家玩法说明](../../玩法说明.md)、[开发维护指南](../../开发维护指南.md)和当前源码为准。

## 背景与目标

本设计稿记录的旧版演出玩法以固定的 32 个节拍时刻为中心：玩家在节拍到达时触发同一个按钮，系统按时间差计分。原目标是把三场演出改成数据驱动的下落音符玩法，加入位置与手势判定，同时保留当时已有的单机经营赛季、音频时钟、演出暂停恢复和结算流程。

实施按一场完整切片的顺序推进：第一场覆盖全部音符类型并打通演出到结算；验证后将同一规则和数据格式迁移至第二、第三场。最终三场均使用新玩法。

## 范围

### 包含

- Tap、Hold、Flick、Drag 四种音符。
- 固定白色斜判定线、纯黑谱面区域、蓝色键盘光标和红色圆形 Flick 音符。
- 键盘 A/D 沿判定线左右移动；空格执行接触。鼠标和触屏支持点按、按住、滑动和跟随。
- 难度影响音符下落速度，并保留现有判定窗口、分数倍率和经营奖励倍率。
- 每场演出的基础得分倍率递增；连击贡献额外分数，不对总分作人为封顶。
- 准确率单独归一化，用于评级及现有经营奖励。
- 实时演出界面显示分数、连击、准确率和谱面进度。

### 不包含

- 联网排行榜、账号、云存档或多人玩法。
- 谱面编辑器、外部音频导入或新音频素材。
- 赛季经济、现有经营行动、档案数量和本地存档格式重做。

## 已确认的交互与判定

### 谱面空间与时间

- 演出谱面区域使用纯黑背景；站点其他页面继续使用现有主题。
- 判定线保持固定的白色斜线。音符从其上方落向判定线。
- 每个音符目标位置使用舞台宽度归一化的横坐标表示。白线纵坐标由该横坐标和固定线段几何关系计算。
- 键盘蓝色光标的横坐标由 A/D 控制，纵坐标始终投影到白色判定线上，不接受 W/S 或方向键移动。
- 图表命中时刻以现有音频引擎播放进度为准。难度速度只改变视觉下落速度及音符提前出现的时刻，不改变谱面命中时刻。

### 音符输入

| 类型 | 键盘 | 鼠标 / 触屏 | 判定结果 |
| --- | --- | --- | --- |
| Tap | 光标对准目标后按空格 | 在目标时刻点按音符 | 在目标位置与时间窗口内判 Perfect 或 Good；否则 Miss |
| Hold | 头部到线时按空格并保持到尾部通过 | 按住音符并持续接触至尾部通过 | 头部时间决定 Perfect/Good；未开始、提前松开或未保持至尾部均为 Miss |
| Flick | 光标对准目标后，在窗口内按指示方向快速按 A 或 D | 在窗口内按指示方向快速滑动 | 方向和时间均有效时判定；否则 Miss |
| Drag | 按住空格，并用 A/D 跟随谱面轨迹 | 持续接触并跟随轨迹 | 头部时间决定等级；接触中断或未跟随至尾部为 Miss |

键盘 A/D 为连续横向移动；Flick 使用方向键的单次快速输入信号，不要求空格。Flick 仅使用左、右方向，以匹配键盘输入约束。鼠标和触屏输入由指针坐标与接触状态驱动。

首版键盘光标移动速度为每秒 1.0 个舞台宽度，并限制在白线两端内。Tap、Hold 与 Flick 的目标位置，以及 Drag 的起点，使用舞台宽度 3.5% 的位置容差，限制在 20 至 36 CSS px。鼠标/触屏 Flick 必须在 160ms 内向指示方向移动至少舞台宽度的 5%；键盘 Flick 以命中窗口内、方向正确且未重复的 A/D keydown 作为一次快速输入信号。Drag 跟随轨迹时使用相同位置容差；偏离超过 100ms 或接触中断则该音符 Miss。以上空间数值是首版默认调校参数，不改变时间判定窗口。

### 判定窗口与下落速度

| 难度 | Perfect 窗口 | Good 窗口 | 下落速度倍率 | 原有分数倍率 | 原有奖励倍率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 轻松 | ±130 ms | ±230 ms | 0.85× | 0.9× | 0.9× |
| 标准 | ±90 ms | ±170 ms | 1.0× | 1.0× | 1.0× |
| 聚光灯 | ±70 ms | ±130 ms | 1.2× | 1.25× | 1.25× |

标准难度的音符默认提前约 1.5 秒出现；其他难度根据速度倍率调整出现时间，使其仍在同一谱面时刻抵达判定线。下落速度、判定窗口和得分倍率分别配置，互不替代。

### 计分、连击与评级

- 单个完整音符只产生一个最终判定。Hold/Drag 在尾部完成前不入账；持续操作失败则该音符记为 Miss。
- 基础判定分：Perfect 1000、Good 650、Miss 0。
- 三场演出的阶段倍率依次为 1.0×、1.25×、1.5×。
- 命中音符后先增加连击，再计算该音符的分数：`round(基础判定分 × 阶段倍率 × 难度分数倍率) + 连击数 × 10`。Miss 计 0 分、清零当前连击且不获得连击加分。总分不应用固定上限。
- 准确率为所有音符基础判定分之和除以 `音符总数 × 1000`。阶段倍率、难度分数倍率和连击加分不进入准确率。
- 保留现有评级阈值：S ≥ 95%，A ≥ 82%，B ≥ 65%，其余为 C。结算继续使用现有准确率映射到经费与热度的规则。

## 谱面数据

每场演出保留现有 32 个节拍锚点及 BPM。首版将每个锚点映射为一个音符事件，谱面可改变音符类型和横向位置；长音符使用持续时间，Drag 使用相对路径点，Flick 使用方向。第一场确保四种类型均出现，后两场可复用同一数据契约并逐场提高 BPM、位置变化和类型组合变化；不增加新依赖或外部素材。

建议的谱面事件字段：

```js
{
  id: 'show-1-note-01',
  type: 'tap',
  hitMs: 600,
  x: 0.5,
  durationMs: 0,
  direction: null,
  path: []
}
```

`hitMs` 与路径点 `offsetMs` 均相对本场开始计时。`x` 和路径点 `x` 范围为 0 到 1；Drag 的 `path` 由按时间递增的 `{ offsetMs, x }` 点组成，纵坐标始终由固定判定线推导。仅适用的字段填写非默认值：Hold 使用 `durationMs`，Flick 使用 `direction: 'left' | 'right'`，Drag 使用 `durationMs` 与 `path`。标准难度的完整下落距离对应 1500ms；其他难度依据速度倍率从场景顶部提前出现，并保持 `hitMs` 不变。谱面测试检查唯一 ID、有效类型、递增且有限的时间、归一化坐标、正的长音符持续时间及有效 Flick 方向。初版谱面不安排需要键盘同时维持两个互斥接触的重叠长音符。

## 模块与数据流

| 模块 | 职责 |
| --- | --- |
| `src/content.js` | 难度配置与三场演出的数据化谱面 |
| `src/rhythm.js` | 生成音符时序、空间/时间判定、长音符状态、计分、准确率与评级；保持为可独立单测的领域逻辑 |
| `src/controls.js` | 绑定并解绑 A/D、空格、鼠标和触屏输入；维护按下状态，避免重复键和指针兼容事件重复计分 |
| `src/stage.js` | 绘制黑色谱面、白色判定线、下落音符、轨迹与蓝色光标；根据当前舞台尺寸重算几何 |
| `src/main.js` | 维护演出生命周期、调用引擎和输入/判定模块、更新 HUD、暂停/恢复并将总结交给经营结算 |
| `src/progression.js` / `src/storage.js` | 沿用现有结算与存档契约；只接收分数、准确率、评级、最高连击及现有经营结果 |

音频引擎的播放头是唯一时间源。渲染循环读取播放头和当前运行态，计算音符位置并更新 HUD；输入事件将时间戳、位置、方向及接触状态交给判定逻辑。判定结果更新本场统计，整场结束时只把总结传入 `settleShow` 并存档。

## 暂停、恢复与失败处理

- 使用现有音频引擎暂停和恢复；暂停期间播放头、音符、光标移动和长音符状态全部冻结。
- 页面进入后台时继续自动暂停，恢复后从原播放头继续，不重复发放命中结果。
- 音频不可用时沿用现有单调时钟回退，视觉演出和判定仍可运行。
- 控件在演出视图卸载时解绑；失焦或暂停时清理瞬时按键/指针接触状态，避免恢复后卡键。
- 保存失败时保留当前会话可玩；继续显示现有存档错误提示，不阻断结算。
- 尊重 `prefers-reduced-motion`：保留谱面位置和可判定性，减少非必要的舞台脉冲效果。

## 兼容性与非功能要求

- 不改变当前单人本地存档结构与版本，不要求迁移旧存档。
- 不改变三场经营流程、难度选择时点、暂停按钮、音量/静音设置和结算奖励计算。
- Canvas 继续响应式缩放并限制像素比；判定位置和命中半径使用舞台坐标转换，不依赖固定视口尺寸。
- 演出界面提供 A/D、空格和指针操作说明；判定结果使用现有 `aria-live` 区域，准确率与连击以文本显示。
- 不引入联网服务、外部音频依赖或新的运行时包。

## 验收标准

1. 三场演出均以四种音符类型完成；每场 32 个锚点及既有 BPM 保留。
2. 音符按命中时刻与难度速度正确预览并抵达判定线；难度越高下落越快，但命中时刻不变。
3. 键盘光标只沿白色判定线横向移动；W/S 和方向键不会移动光标；空格、Flick 与长音符输入符合本规格。
4. 鼠标与触屏可以完成点按、Hold、Flick 和 Drag，且一次物理操作不重复判定。
5. Perfect/Good 边界、位置容差、Miss、长音符中断、连击重置与各阶段计分均由单元测试覆盖。
6. 准确率不因阶段倍率、难度分数倍率或连击加分改变；评级和经营奖励仍按准确率结算。
7. 开始、暂停、恢复、切后台、音频回退、结束、经营阶段、本地记录和旧版存档流程均通过回归测试。
8. 全量 `node --test` 通过；桌面与移动视口检查无溢出、遮挡或不可操作音符。

## 实施阶段

1. 为第一场建立谱面与纯逻辑测试，接入四类音符、判定和计分。
2. 接入键盘/指针操作、Canvas 渲染和实时 HUD；验证暂停、恢复、音频回退及单场结算。
3. 将同一谱面契约应用于第二、第三场，补充全赛季回归测试。
4. 在桌面和移动视口运行完整赛季并检查结算、经营奖励及本地存档兼容。
